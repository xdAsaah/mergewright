# 选项目：值不值得去

> 触发：要评估一个新仓库、或判断某个项目要不要继续投入。
> 核心原则：**star 多 ≠ 值得去**。成熟项目合并率高，但席位已满，你的 5 个 PR 只能排到第 200 名。

## 一、先算三个硬指标

用 `scripts/prtool.py status --repo <owner/repo>` 取数，别看纸面合并率。

| 指标 | 算法 | 门槛 |
| --- | --- | --- |
| **外部合并率** | 近 20 个已关闭 PR 中，非 MEMBER/OWNER/COLLABORATOR 作者的合并数 ÷ 外部作者总数 | ≥ 50% |
| **外部作者数** | 近 100 个已关闭 PR 里，去重后的外部合并作者 | ≥ 5 人（≥ 8 更佳） |
| **通道活性** | 最近一次合并时间、open PR 最大等待、批量合并占比 | 最近合并 ≤ 7 天；最老 open ≤ 14 天 |

**单人通道降档**：外部合并作者 < 5 人的项目，合并率再高也降一档评估——那通常意味着只有一个人在合，他停手项目就死。

## 二、评分卡（100 分）

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 席位可得性 | 28 | top10 贡献者的 commit 门槛；贡献者数 ÷ (stars/万) |
| 新贡献友好性 | 20 | 合并作者数、合并 ≥2 次的作者数、有没有新手引导文档 |
| 维护者积极性 | 15 | 人类首响中位、open PR 零回应率、近 7 天有没有 review |
| 方向含金量 | 22 | **这个项目在你的目标方向上吗？** 见下方「含金量怎么定」 |
| 合并可达性 | 15 | 中位 PR 规模、是否批量合并窗口、CI 是否三平台 |

**C 项否决线**：维护者积极性 ≤ 5 分 → 不作主力，总分再高也不去。

### 含金量怎么定

这一项 22 分，但**标准由你的目标决定，不能写死在方法里**。先看 `preferences.md` 的「长期目标」一节：

| `preferences.md` 里写了什么 | 怎么打分 |
| --- | --- |
| 有明确赛道（如「AI agent 方向」） | 项目属于该赛道 → 18–22；相邻 → 10–17；无关 → 0–9 |
| 只写「积累开源经验」 | 不看领域，改看：项目活跃度、代码质量、是否有可学的架构 → 按你的判断给分 |
| 没写 | **先问用户**，别自己假定方向 |

**没有方向偏好时，不要用「是否 AI 热点」这类通用热度当标准**——那是某个人的目标，不是所有人的。

## 三、六个统计陷阱

1. **只统计已关闭 PR** 会系统性高估接受度——必须同时看 open 积压。
2. **`author_association=CONTRIBUTOR` 不等于外部贡献者**——维护团队成员几乎都落在这个值里。必须同时看「非成员合并占比」和「合并作者去重」。
3. **合并快 ≠ 维护者积极**——可能是同一分钟批量合并。看合并时有没有指向具体代码的留言。
4. **全量关闭 PR 算首响会被稀释**——自合并和 bot PR 要剔除，只统计一次性外部作者的 PR。
5. **AI 代理账号要剔除**——Claude、Copilot、Cursor、Codex、dependabot、renovate。
6. **「最老 open PR」不是好指标**——用积压率（open 数 ÷ 近 30 天合并数）。

## 四、难度分级（决定第一个 PR 做什么）

| 级别 | 特征 | 例子 |
| --- | --- | --- |
| D1 | 单文件、行为明确、有现成测试文件可加 | 文案错误、边界条件 |
| D2 | 跨 2–3 文件、要加测试夹具 | 平台兼容、路径规则 |
| D3 | 单模块行为改造 | 状态机分支、重试策略 |
| D4 | 跨模块 | 协议变更、并发模型 |
| D5 | 架构级 | 不要作为前几个 PR |

**第一个 PR 选最容易合的（D1），不是最有价值的。**

## 五、大仓 vs 小仓

- **头部大仓**（贡献者数百）：合并难度高、杠杆低。适合「提一两个证明能进」，不适合作为主战场。
- **主力小仓**：top10 门槛 ≤ 5 commits、外部合并作者 ≥ 5 人、人类首响 < 24h、非成员合并 ≥ 25%。
- 成熟项目即使合并率高，**相同工作量在与你目标更相关的项目里价值更高**——具体怎么衡量看你自己的目标，见 `preferences.md`。

## 六、什么时候该止损

- 连续 2 个 PR 14 天无 review
- 外部 PR 合并停摆超过 2 周
- 维护者明说「这个我自己改」后同类问题再提一次仍被忽略

止损后在 `projects/_index.md` 标「已止损」并写原因，**不删除记录**。
