# 初始化：第一次用这个 skill

> 触发：数据目录里还没有 `preferences.md`，或用户说「重新设置一下」。
> **目标：问 3 个只有用户知道的问题，其余全部推导或读出来。**

## 零、先确保数据目录存在

**在问任何问题之前做这一步。** 数据目录默认 `~/.mergewright/`，所有执行记录都在那里。

```bash
python scripts/prtool.py init
```

它会从 skill 包的 `_seed/` 拷出骨架（`preferences.md`、`lessons.md`、`conventions/`、`projects/`、`state/`），**已存在的文件不覆盖**，重复跑是安全的。

如果用户想放别的位置，用 `--data <路径>` 或设环境变量 `MERGEWRIGHT_HOME`。定了之后告诉用户：「以后所有记录都在 `<路径>`，换 agent 也是这一份。」

**检查是否已经初始化过**：

```bash
python scripts/prtool.py check
```

输出里会分两段——「skill 包」和「数据目录」。数据目录不存在就是没初始化过。

## 一、先判断是哪一级初始化

| 情况 | 做什么 |
| --- | --- |
| 数据目录没建，或没有 `preferences.md` | 做**全局初始化**（本文第二到四节），只做一次 |
| 有 `preferences.md`，但要加新项目 | 跳过本文，直接读 `references/onboard-project.md` |
| 用户说「改一下止损线」 | 只改 `preferences.md` 对应行，标日期 |

**`preferences.md` 是全局的，不是每个项目一份。** 进新项目时先读它，缺什么才问什么——不要重复问已经答过的。

## 二、全局初始化：只问这 3 个

一次问完，**不要一个个挤牙膏问**。用 `AskUserQuestion` 或直接列出选项让用户选。

### Q1 你做开源贡献的目的是什么？

| 选项 | 特征 | 推导出的策略 |
| --- | --- | --- |
| A. 求职 / 简历素材 | 需要可见成果，重视项目知名度 | 倾向中等以上知名度；PR 标题要清晰；合并记录整理成清单 |
| B. 学技术 / 读优秀代码 | 过程比结果重要，愿意慢 | 倾向代码质量高、review 认真的项目；可接受低合并率 |
| C. 进入某个社区 / 长期参与 | 看重关系和持续存在 | 倾向维护者活跃、社区友好的项目；建议先提 issue 再提 PR |
| D. 修自己实际用到的问题 | 需求驱动，不挑项目 | 跳过评分卡，直接从自己用的项目挖 |

### Q2 你每周能投入多少时间？

| 选项 | 特征 | 推导 |
| --- | --- | --- |
| A. < 2 小时 | 只能碎片化 | 同时 1 个项目；只做 D1；响应时限 72h |
| B. 2–5 小时 | 一周一个完整 PR | 同时 1 个项目；D1–D2；响应 48h |
| C. 5–15 小时 | 可并行排查 | 同时 2 个项目；D1–D3；响应 24h |
| D. 15 小时以上 | 接近全职 | 同时 2–3 个项目；可做严重线；响应 24h |

### Q3 你的技术栈和想去的领域？（多选，各含「不限」）

**技术栈**（选你写得动的；选「不限」表示都可以）

| 选项 | 选项 | 选项 |
| --- | --- | --- |
| TypeScript / JavaScript | Python | Go |
| Rust | Java | C++ |
| 其他（自己填） | **不限** | |

**领域**（选你感兴趣的；选「不限」表示都可以）

| 选项 | 选项 | 选项 |
| --- | --- | --- |
| AI / Agent | Web 后端 | 前端 |
| 数据 / 数据库 | 基础设施 / DevOps | 安全 |
| 嵌入式 | 其他（自己填） | **不限** |

> **为什么必须问**：没有它，`choose-project.md` 的评分卡只能给空气打分——推荐一个你不会 Rust 的 Rust 项目等于浪费一轮。
> 选了「不限」→ 评分卡的技术匹配维度给满分，不额外扣分。

### 三个问题的推导结果

Q1 + Q2 答完后，**不要另问**，直接按下面规则推导，展示给用户确认：

| 策略项 | 推导规则 |
| --- | --- |
| **止损线** | Q1=A + Q2∈{A,B} → 2 个 PR / 14 天<br>Q1∈{B,C} 或 Q2∈{C,D} → 3 个 PR / 21 天<br>Q1=C + Q2=D → 4 个 PR / 30 天 |
| **低价值 PR 提不提** | Q1=A → 信任建立前不提（纯测试进不了简历）<br>Q1=B → 可以提，能学流程<br>Q1=C → 可以提，是社交敲门砖<br>Q1=D → 不提，没意义 |
| **响应时限** | 由 Q2 直接给出（见上表） |
| **同时几个项目** | 由 Q2 直接给出（见上表） |

展示方式：**「根据你的目的和时间，建议止损线 2 个 PR / 14 天、信任建立前不提低价值 PR。要改吗？」** 用户随时可以覆盖，覆盖后记进 `preferences.md` 并在备注写「用户指定」。

## 三、身份检查：不问，跑脚本

**提交身份不用问用户**——git 里有、凭据库里有，直接读。

```bash
python scripts/prtool.py whoami
```

脚本检查四件事并给出结论：

| 检查项 | 来源 | 正常 | 异常时给什么 |
| --- | --- | --- | --- |
| git 是否安装 | `git --version` | 有输出 | 没装 → 三平台安装命令，到这就停 |
| 提交名 | `git config --global user.name` | 有值 | 拿不到就用凭据库里的账号名，给出 `git config` 命令 |
| 邮箱 | `git config --global user.email` | 含 `noreply` | 是真实邮箱 → 警告会公开，给出 noreply 地址（已自动查好数字 ID） |
| 平台账号 | `git credential fill` | 有 username | 未登录 → 两段式引导（先登录，再重跑） |

**三种典型情况**：

| 情况 | 脚本输出 | 你要做的 |
| --- | --- | --- |
| 已配置好 | 「身份已就绪，无需操作」，exit 0 | 无 |
| 全新机器，什么都没设 | 列出两条 `git config` 命令，名字自动填 | 复制执行，重跑一次 |
| 用了真实邮箱 | 警告 + 给出 noreply 地址 | 复制执行，重跑一次 |

**为什么重要**：真实邮箱会公开出现在每一个 commit 里，永久留在仓库历史中，事后改不了。这是初始化阶段唯一不可逆的错误。

### 机器上完全没有 GitHub 信息时

这是最常见的真实场景：新电脑、刚装 git、从没提交过。脚本会分阶段引导，**每一步的输出都不一样**：

| 阶段 | 脚本说什么 | 做什么 |
| --- | --- | --- |
| **git 都没装** | 列出三平台安装命令 | 装 git，重跑 |
| **装了 git，没登录** | 「这台机器还没有配置过 GitHub 身份」，给 3 步流程 | 见下 |
| **登录了，没设身份** | 自动读出用户名，给出两条已填好的 `git config` 命令 | 复制执行 |
| **都配好了** | 「身份已就绪」 | 无 |

**没登录时的 3 步流程**（脚本会原样打印）：

```
第 1 步 · 登录
  gh auth login
  # 选 GitHub.com → HTTPS → 用浏览器登录

第 2 步 · 重跑本命令，会自动读出用户名和 ID
  python scripts/prtool.py whoami
  # 这次它会直接给你两条已填好的 git config 命令，复制执行即可

第 3 步 · 再跑一次确认
  python scripts/prtool.py whoami
```

**为什么是两段式**：没登录就不知道你的用户名，也就不知道数字 ID，没法拼出 noreply 邮箱。所以必须先登录、再重跑。脚本不会让你猜。

**没有 gh CLI 也能走通**：

- 第一次 `git push` 时 git 会弹浏览器登录，登录后同样重跑 `whoami`
- 或者完全不登录：去 GitHub → Settings → Emails → 勾「Keep my email addresses private」，页面直接显示完整 noreply 地址，手动填进 `git config`

### 手动设置（脚本跑不了时）

如果机器上没有 Python，手动两步：

```bash
# 1. 设名字（用你的 GitHub 用户名）
git config --global user.name "你的用户名"

# 2. 设 noreply 邮箱
#    数字 ID 从 https://api.github.com/users/<你的用户名> 的 id 字段取
#    （这个地址不需要登录也能访问）
git config --global user.email "<数字ID>+<你的用户名>@users.noreply.github.com"
```

也可以去 GitHub 设置页 → Emails → 勾选「Keep my email addresses private」，
页面会直接显示你的 noreply 地址，格式一样。

## 四、全局初始化还要确认的三件事

这三件不用问，但要让用户知道：

1. **汇报语言**：默认跟用户当前对话语言。用户说「用英文汇报」再改。
2. **止损后的处理**：不删记录，只在 `projects/_index.md` 标「已止损」。这是防止重复调研的关键。
3. **哪些事会来问用户**：是否提某个 PR、要不要止损、改方向。**技术细节不问**。

## 五、产出

1. `preferences.md`：按本文第二节的答案和推导结果填写，每条带日期
2. `projects/_index.md`：只有表头，没有项目行
3. `state/prs.jsonl`、`state/scans.jsonl`：空文件

**不要**在初始化时创建 `conventions/` 或 `projects/` 下的任何项目目录——那些等真正进项目时再建。

**不要**因为初始化就去读 `conventions/_TEMPLATE.md`——那是给「进项目」时用的（见 `onboard-project.md`）。

## 六、初始化完成后，告诉用户什么

一段话，说清三件事：

```
设置已存到 preferences.md：
- 响应时限 24 小时，止损 2 个 PR / 14 天
- 低价值 PR 信任建立前可提
- 目标方向：<用户答的>

身份检查：git 提交名 <从脚本读到的>，noreply 邮箱，无需改动。
（若脚本报了问题，把命令贴给他，让他执行完重跑 whoami）

以后每次会话我会先读这个文件，不会重复问。
要改随时说「以后 XX」。

下一步：给我一个仓库，我先跑进场采集（onboard-project.md），
或者你说「找个项目」，我按评分卡筛。
```

## 七、什么时候该重新初始化

| 情况 | 动作 |
| --- | --- |
| 用户说「我换方向了」 | 只改 `preferences.md` 的「长期目标」，标日期，旧值留在备注里 |
| 用户说「止损太严/太松」 | 只改对应两行 |
| 用户换了台机器 / 重装 | `preferences.md` 丢了就重跑本文第二节，并重跑 `whoami` |
| 换了 GitHub 账号 | 重跑 `whoami`，`preferences.md` 的「身份」一节同步更新 |

**不要因为进新项目就重跑全局初始化。** 项目级的问题在 `onboard-project.md`。
