# 项目档案模板

> 新建项目：先跑 `scripts/prtool.py onboard`，再复制整个 `_template/` 为 `projects/<项目名>/`。

## 四个文件的职责

| 文件 | 写什么 | 什么时候更新 |
| --- | --- | --- |
| `profile.md` | 基本盘、仓库地图、领域约定、维护者画像 | 首次进入时写全；有新观察时补 |
| `ledger.md` | 每个 PR 一节：改动、复现、结果、维护者补了什么 | 每次 PR 有结果时 |
| `excluded.md` | 已排除方向，带证据+结论+日期 | 每轮扫描后 |
| `candidates.md` | 进行中 / 待提 / 待验证 / 已筛掉四档 | 每次会话结束；**开分支改代码前必写「进行中」** |

**规则（commit 规范、测试命令、维护者政策、不变量）不写在这里**，写 `conventions/<项目>.md`。
**跨项目经验不写在这里**，写 `lessons.md`。

## profile.md 至少要有

- 仓库名、语言、许可、运行环境、依赖情况
- 仓库地图（哪个目录做什么、改动风险）
- 领域约定（写代码前必读的几条，带文件路径）
- 维护者画像（沟通语言、review 风格、补过什么、合并节奏）

## ledger.md 每条至少要有

- PR 号、分支、基点、文件数、增删行数
- 改动摘要
- 复现方式（红→绿的具体数字）
- 结果（合并时间 / 关闭原因 / 在审）
- **维护者改了什么**（最有价值）
- 教训 —— **只对这个项目成立的**。换个项目也成立的写进 `lessons.md`，别堆在这里。

## excluded.md 每条至少要有

- 方向
- 证据（文件:行号、实测结果、文档引用）
- 结论
- 日期

**判定为「不成立」的也不删**——下次有新证据可以翻案，但必须说明新证据是什么。

## candidates.md 四档

- **进行中**：已开分支、改了代码，还没提 PR。**开分支之前就写**，否则会话断了下一个 agent 会重做
- **待提**：证据齐，只等用户同意
- **待验证**：有线索，缺关键事实（要写清缺什么）
- **已筛掉**：指向 `excluded.md`
