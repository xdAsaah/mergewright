# <项目名> issue 追踪

> **作用：避免重复看同一个 issue，也避免碰别人已认领的。**
> 扫 issue 用 `python scripts/prtool.py issues --repo <owner/repo>`。
> 只记值得留档的，不要把所有 issue 都抄一遍。

## 一、我开的 issue

| # | 标题 | 开的日期 | 目的 | 状态 | 下一步 |
| --- | --- | --- | --- | --- | --- |
| | | | 探方向 / 报告 bug | 等回应 / 已回应 / 已转 PR | |

**状态取值**：等回应 / 维护者同意 / 维护者拒绝 / 维护者说他自己改 / 已转 PR / 已关闭。

**维护者说「我自己改」→ 立刻停手，不要提 PR，也不要再提同类。**

## 二、看过的、不打算做的

> 防止下次重看。写清「为什么不打算做」。

| # | 标题 | 为什么不做 | 日期 |
| --- | --- | --- | --- |
| | | 已有人认领 / 设计未收敛 / 太大 / 维护者否过 | |

## 三、别人认领中的（不要碰）

| # | 标题 | 认领人 | 日期 |
| --- | --- | --- | --- |
| | | | |

**每次扫完 issue 更新这一节。** 认领状态会变，超过 30 天的记录要重查一次。

## 四、值得关注的（还没决定）

> 有潜力但还没想清楚要不要做的。写清「卡在哪」。

| # | 标题 | 类型 | 卡在哪 |
| --- | --- | --- | --- |
| | | fix / test / feat | 需要更多信息 / 等维护者回 / 要看代码才知道 |
